## 1. 结论速览

### 1.1 一句话结论

这是一套**工程质量高、边界意识强**的"面向 LLM 的蓝图阅读包"。核心决策——**确定性生成伪代码、分层按需披露、显式声明不确定性、SHA1 交叉校验**——在"边界声明 + 完整性校验"维度上比本次查阅的同类开源样本（NodeToCode / blueprint-analyzer / BlueprintSerializer）更系统；但同类样本有限、未做同条件实测，**不构成整体优劣结论**。

在本次核验范围内**未发现语义或校验缺陷**；提出的问题均属工程性设计层面，且**绝大多数已落地**。

## 2. 产物与机制概览

**定位**：把蓝图导出为"面向 AI 的按需阅读包"，让 LLM/程序在不加载完整快照的前提下准确理解蓝图逻辑。主要阅读文本压缩到个位数百分比——设计目标**不是"无损压缩"，而是"可定位的按需读取 + 明确的不确定性标记"**。

**产物位置**：`Saved/XTools/BlueprintExports/<资产名>_<完整对象路径SHA1>/`

**包内结构**：

| 路径 | 作用 |
|---|---|
| `00_START_HERE.md` | 入口 / 图索引（禁止递归读取） |
| `01_Manifest.json` | v2 机器清单，带 `logic_sha1` / `evidence_sha1` |
| `02_ReadingContract.md` | 通用阅读契约 + 伪代码语法 v1 |
| `05_Query.py` | 只读查询器（纯标准库，3.9+，不需 UE） |
| `10_Logic/Gxxxx.pseudo.md` | 确定性伪代码（不调 LLM） |
| `20_Evidence/` | `00_Asset.json`（变量 / class_defaults / 组件 / Timeline / coverage）+ `Gxxxx.json`（节点 / 引脚 / 边） |
| `30_Dependencies/Mxxxx.*` | 按需标准宏定义 |
| `90_Full/<资产名>.json` | 引擎原始快照，仅审计（查询器不消费） |

根目录另有 `00_INDEX.json`（机器可读跨包索引）与面向人的 Markdown 资产索引。

**阅读纪律**：读入口 → 读一次契约（同 SHA1 可跳过）→ 选 `10_Logic` 伪代码 → 证据不足才查 `20_Evidence` → `90_Full` 仅审计。默认预算 **40 节点 / 16000 字符**。

**查询器命令**：

```
outline [--include-macros]       图 / 宏索引（按预算发现）
find --query <kw>                全文检索
node --graph G --node N [--evidence]   单节点
slice --graph G --node N [--follow [--depth N] [--max-graphs N]]   可达集
deps --graph G [--node N]        正向函数 / 宏调用
assets --graph G [--node N]      有类型依据的输入默认资产引用
impact --target <X> [--depth N]  反向影响面（谁调用了我）
diff --directory <新包> --against <旧包>   快照对比
--node-guid <完整GUID> / --snapshot <id>   稳定身份定位
```

`--include-macros` 只列宏索引（`id`/`name`/`node_count`），与 `--graph Mxxxx` 互斥。

**身份与版本机制**：manifest 记录 `query{path, protocol_version, sha1}`、`reading_contract{path, version, sha1}`、`pseudo_format_version`；`outline` 每项返回 `logic_bytes` / `evidence_bytes`。查询器**仅当自身就是包内副本时**校验 `query.sha1`，外部查询器只需协议版本兼容 → 保留离线可分发。

**校验链（七类）**：契约体哈希、契约版本、协议版本、查询器身份（仅自身副本）、`logic_sha1`、`evidence_sha1`、路径越界。错误一律以 `{"error": ...}` + 非零退出码返回。

**能力标志 `features`（10 项）**：`local_initialization`、`dependency_navigation`、`semantic_hints`、`standard_macro_definitions`、`reading_contract`、`format_contract`、`classified_fallback`、`persistent_identity`、`standard_macro_iteration`、`spawn_exposure_hints`。读者按能力降级，不硬失败。

### 4.2 一个易误读的字段：`class_defaults.flags`

`class_defaults.properties[].flags` 是 `PropertyFlagsToString` 生成的**文字摘要**，只枚举 **六项常用标志**：`Edit` / `BlueprintVisible` / `BlueprintReadOnly` / `Config` / `DisableEditOnInstance` / `DisableEditOnTemplate`。

**它不是完整标志集**，不能用于判断 `ExposeOnSpawn` 等编译期 flag。判断变量标志必须用：

- `variables[].property_flags` —— **数值位**，如 `5 = CPF_Edit(0x1) | CPF_BlueprintVisible(0x4)`；
- `variables[].metadata` —— `FBPVariableDescription::MetaDataArray` **全量导出**，含 `ExposeOnSpawn` 等一切 `UPROPERTY` meta。

引擎侧印证：UE 5.3 `KismetCompiler.cpp` 由变量元数据 `ExposeOnSpawn` 派生 `CPF_ExposeOnSpawn`。

**处置（落点优于原建议）**：实现方没有把提示补进 `class_defaults` 摘要，而是**前移到变量节点的伪代码**，让 AI 读到变量的那一刻就知道它可能从外部初始化：

```
  binding: "self_member" expose_on_spawn=true [spawn_argument_possible; default_not_constant]
```

- 在变量节点的 `binding:` 行追加，`node` / `slice` / `slice --follow` 均保留。
- **防误标规则**：仅当 `binding_origin == "self_member"` 且 `is_self_context` 且非局部且非外部成员且 GUID 有效，再用该 GUID 在本资产 `variables[]` 查到声明、**名称一致**、`metadata.ExposeOnSpawn == "true"` 时才追加 —— **同名局部 / 外部成员 / 外部宏不会被误标**。
- **契约已同步**：声明"表示可在 Spawn 时传入，**不证明实际已传值**"；"**缺少提示不证明变量恒定**"；以及"`flags` 仅为常用标志摘要；默认值不是运行时不变量"。
- **完整元数据仍在证据层**（`variables[].metadata` 按需查证），伪代码只给提示。

## 5. 实现层结论（O1–O6）

| 项 | 原问题 | 结论 |
|---|---|---|
| **O1** 伪代码渲染层丢信息 | 分类层产出 ~65 种 `kind`，`NodeText` 只渲染 19 种 → **46 种已分类 kind 退化为 `opaque`**（`switch` / `timeline` / delegate / struct / input 等）。危害不是"降级"而是**标签语义冲突**：契约把 `opaque` 定义为"未分类"，此处却是**已精确分类** | ✅ **完全落地，方案优于建议**。未逐 kind 补模板，而是加**通用兜底**：`classified "<kind>" "<title>" [class=…; see_evidence; not_full_compiler_semantics]` + 完整 `semantic:` 行 —— **一次覆盖全部 kind，消灭了"分类层/渲染层对齐"这个缺陷类别本身**。防复发：KindCoverage 测试枚举 **71 种 kind**，断言"已分类 kind 永不回退 opaque" |
| **O2** 依赖图不含资产引用 | `dependency_targets` 只认 `call_function` / `macro_instance`；参数 / 默认值里的资产引用（SpawnActor 的 Class、Niagara 的 SystemTemplate、Timeline 的 Curve…）完全不在依赖图 → **影响面分析静默返回空集**（返回 `ok` 但漏项，比报错更危险） | ✅ **完全落地，解耦方案优于建议**。新增独立 `assets` 子命令 + `asset_reference()`，只接受 `object/class/softobject/softclass`，排除容器与 `/Script` `/Temp` `/Memory` `/Transient`，区分 hard/soft；`deps` 加 `asset_reference_hint` 交叉引导 —— `deps` 保持"正向调用目标"单一语义，hint 消除"静默空集"风险。metadata 如实声明 `scope=typed_unconnected_input_defaults` / `complete_asset_graph=false` |
| **O3** 多出口节点缺分支摘要 | 建议对多出口节点追加 `branches: then->@N22, else->@N63` | ⏸ **暂缓（唯一待办）**。调研三条一致：描述性图表示可减少 LLM 漏掉 gateway；结构化图表示中 JSON 综合最佳；流程图任务 Graphviz 最有效。**暂缓理由**：① 当前 `exit "then" -> @X` **已显式枚举**多出口；② 摘要主要是**重复现有信息**、增加上下文体积；③ "多出口"语义**并不统一**（`switch`=选择 / `sequence`=顺序派发 / 异步=回调）；④ 缺"当前格式 vs 加摘要"的**理解效果对照评测**。**不能由此断言摘要一定无效。** 若采纳须递增 `pseudo_format_version` |
| **O4** 查询器效率与预算 | `find` 匹配面过宽 / 先收集后裁剪 / 候选包重复校验 / 协议版本硬失败 | ✅ **4/4 落地**。`bounded_results` 边扫描边计数；`GraphValidation` 缓存避免重复 `manifest()`；协议错误返回 `supported`/`received`/`field`（**仍拒绝未知版本**，协商 ≠ 接受）。`find` **保留全文匹配语义**（覆盖引脚/默认值/注释，是现有用途） |
| **O5** 导出器热路径效率 | `PinLabel` 重复计数 O(P) / `PinIndexInNode` 线性扫描 O(N·P²) / 图列表与图内排序枚举两遍 | ✅ **2/2 落地**。构造期预统计 `PinNameCounts` + `FPinIndexCache`（按属主节点懒建，含图外节点）+ `FBlueprintGraphCache`（JSON 与 Markdown 共用）。缓存均为**函数内栈对象**，无 `static` / 全局缓存 |

## 6. 跨图 / 跨资产 / 跨快照（N1–N10）

**N1–N6 全部落地**，落地后在**真实多资产语料**上完成正查 + 反查双向闭合（`deps` 找跨资产目标 → `impact --target` 反查调用者，两端命中，`coverage_complete=true`）。

| 编号 | 项 | 落地形态与要点 |
|---|---|---|

### 6.1 N6 关键操作认知 —— 重新导出会覆盖同目录产物

目录名中 `<完整对象路径 SHA1>` 只派生自**资产对象路径**，与内容无关 → 同资产重导 = 同目录 = **原地覆盖**。正确用法：

1. 第一次导出 → 得到一个包；
2. **在 UE 里改动之前**，把整个包目录**复制到导出根目录之外**；
3. 在 UE 里改动蓝图；
4. 重新导出 → 同目录覆盖，得到新快照；
5. `diff --directory <新包> --against <第 2 步留存的旧包副本>`。

> 副本若留在**同一根目录**内，`00_INDEX.json` 不会收录它，且索引 stale 校验会以索引为准 → 放根目录之外最干净。

### 6.2 N7–N10 补充观察（低优先）

| N7 | `assets` 覆盖边界 | 跳过 `connected` / `linked_to` → 只覆盖"未连接引脚的默认值"。**scope 已在输出声明**（`typed_unconnected_input_defaults`），不算缺陷 |
| N8 | token 效率 | 节点头重复 `kind` / `class`；AST 折叠可省约三成输入长度且精度持平，但**有损**，须先对照评测 |

**另两条低优先观察**：① `FBlueprintGraphCache::Nodes` 的**引用失效约束未标注**（`NodesByGraph.Add` 会因 TMap 扩容使先前返回的引用失效；当前调用点都在同函数内"取引用→用完"，**实际安全**，建议补注释）；② `GraphValidation.key()` 每次调用都做 `base.resolve()`（realpath 系统调用），目标很多时可对 `base` 记忆化 —— **不建议单独立项**。

## 7. 保留的设计意图（明确不建议改）

| 项 | 理由 |
|---|---|
| 阅读路径不受强制约束 | 产物定位是"供 AI 分析的资产包"，模型必须能按问题自由决定追踪范围与证据深度；预算控制应是**成本工具**，不是访问闸门 |
| 紧凑 `@N` 序号 | 局部阅读效率高；跨快照问题由"默认视图暴露 GUID"解决，不改格式 |
| 查询器随包分发 | 已由身份 + 协议版本解决"版本用错"，同时保住**离线可移植** |
| 不做 `unset` 推断 | 缺少证据支撑，强行推断会新增误读面 |
| 宏不内联展开 | 避免 body 复制爆炸；"引用 + 摘要 + 按需展开"是正确取舍 |
| 环不展开、不删边 | 契约显式声明；`selection` 有 `seen` 环保护 |
| `opaque` 保留"不假设无操作"语义 | 该警告本身有价值；只反对把**已分类**节点误标为 `opaque` |
| 预算控制是软约束 | 给自愿用户的成本工具，非访问闸门 |

## 8. 缺陷与观察台账（最终定性）

> 全库 `deps` 普查（577 图）中，非标准记录共 15 条，**全部**落入 F-A 与 F-B —— **无其他异常**。

| 编号 | 问题 | 最终定性 |
|---|---|---|
| **F-A** | **父类事件覆写被误判 `graph_not_exported` —— 系统性假阴性，且正/反查自相矛盾** | ✅ **已修复（14/14，零记录丢失）**。成因：成员索引只收 `kind=="custom_event"`，**排除 `kind=="event"`** → GUID 匹配不上。铁证：同一条条件边，正向 `deps` 说"图未导出"，反向 `impact` **却命中 2 处调用者** —— 自相矛盾即证明是缺陷。修法：索引纳入 `kind=="event"`，按 `node_guid` 匹配（`semantic.event.guid` 全零，不可用），名称回退用 `semantic.event.name`。修复后 `graph_not_exported` **14 → 0**、`ok` 854 → 868，正/反查矛盾消除 |
| **F-B** | **"无效消息节点"产生空目标依赖记录，并使全库 `coverage_complete` 恒为 false** | ✅ **诊断已补齐**。`K2Node_Message` 缺 `resolved_function` → `{raw_target:"", status:"unresolved"}` 且**无 `reason`**；这 1 条使每次 `impact` 都 `coverage_complete=false`，该标志失去区分力。现补 `reason:"missing_target"` + 精确定位到 `K2Node_Message` 的 `dependency_hint`。`coverage_complete=false` **按决定保留**（注释明示"未知调用不能为了报完整覆盖而被排除"）。边界已核对：全库另 8 处 `K2Node_Message` 均正常，仅"无效消息节点"形态出问题 |
| **F-B′** | **诊断被"调用者前缀"饿死 —— 高扇入目标下永远看不到缺口原因** | ✅ **已修复**。诊断原先 append 进**同一个** `ResultItems(max_nodes)`，被调用记录占满 → 仅当"调用者数 < `--max-nodes`"才可见（实测 ForEachLoop 156 调用者：默认预算诊断=0）。修复：**诊断前置到调用记录之前，继续共用现有预算**。修复后默认预算诊断 **0 → 1**，全档预算均可见；245 条记录**内容零变化**（`NEW[1:] == OLD[:-1]`，唯一差异是诊断由队尾提升到队首） |
| **F-C** | 能力标志与载荷无耦合，缺件以裸 `[Errno 2]` 暴露 | ◐ **部分修复**。✅ 缺件已由裸 `[Errno 2]` 变为 `{"error":"missing required file: <绝对路径>"}`。❌ "能力标志与载荷无耦合"（声明 `standard_macro_definitions` 却删 `30_Dependencies/` 时 `outline --include-macros` 仍报计数）**未纳入改动** |
| **F-D** | 参数校验错误信息为固定拼接，会点名不相干的参数 | **非缺陷 —— 可读性瑕疵（校验结果正确）**。仅 `--max-chars` 不合法时错误串同时陈述 `--max-nodes` 约束。**处置**：不专门维护备用方案，以后调整参数提示时**顺手拆分** |
| **F-E-1** | `--node` 不要求有效 GUID | **有意设计，实测坐实**。`--node` 按**快照内编号**定位；即便节点 GUID 损坏也应允许读取其证据 —— 否则**恰好无法检查出问题的节点**。需要稳定身份时用 `--node-guid`（已拒零 GUID 与歧义）。实测：零 GUID 下 `node --node N0` rc=0 且可连 `class_path` 一并返回；`--node-guid 000…0` rc=1。真实语料中零/空 GUID 均为 0，属设计边界 |
| **F-E-2** | 不同错误返回不同信息 | **有意设计，实测坐实**。**版本不兼容**返回 `supported`/`received`/`field`，**供调用方选择兼容版本**；普通参数错误只需说明原因。当前无消费方要求统一错误码，引入完整错误分类体系会增加维护成本 |

### 8.1 已闭合的低优先观察

- **`90_Full/*.json` 的 CRLF**（唯一含 CRLF 的产物，成因是引擎 `TJsonWriterFactory` 写入、行尾跟随 `LINE_TERMINATOR`）→ **已闭合**：全产物 CRLF = 0，且该文件已改为单一 `<资产名>.json`，旧的 `.ai.md` / 人读 `.md` 已退役。
- **项目内自定义宏库未纳入依赖导出** → **已闭合**：实现方把自定义宏库作为**独立包导出**，调用方 `deps` 全部解析为 `ok`、`slice --follow` 可跨包进入宏体、`impact` 可反查全部调用点。
- **跨包 `query_args` 的基准目录未声明** → **已落地**：`navigation()` 给出**绝对** `path_base` / `query_script`，`query_args` 的 `--directory` 亦为绝对路径，任意 CWD 可直接执行。
- **`node --evidence` 超预算返回空 `results`** → **已落地**：`bounded_results` 降级阶梯 —— **先省证据 → 再省逻辑 → 最后丢整条**；`required_max_chars` 可用于一次性恢复。契约明示的合法组合 `truncated=true` 且 `remaining_results=0` 已复现。
- **`node` 两种模式 schema 不同** → **已落地**：两模式**共有** `graph/graph_path/id/node_guid/logic/logic_status/evidence_status`；`--evidence` 仅**追加** `node`/`edges`。
- **`outline` 无完整计数** → **已落地**：新增 `graph_count` / `entry_count` / `result_budget_unit`，**不因截断减少**。
- **`outline` 默认预算在大资产上会截断** → **保留（既有预算保护设计）**：值得在入口提示"图多时先加预算"。

### 8.2 措辞纪律

**不得把"暂缓 / 有意选择"写成"未采纳"或"缺陷"** —— 后者暗示建议被否定或问题成立，与实现方口径不符。发现新观察时，先问"这是实现方的有意选择吗"，再定性。

## 9. 验证方法（可复用）

| 方法 | 做法 |
|---|---|
| **破坏性验证** | 把包复制到临时目录，逐项篡改**副本**（不动原件），观察校验链是否拦截。已覆盖：契约体 / 契约版本 / 协议版本 / 查询器身份（仅自身副本）/ `logic_sha1` / `evidence_sha1` / 路径越界 / 重复与零 GUID / 换入旧版查询器 / 异资产 `diff` / 索引 stale → **全部符合预期** |
| **差分对照** | `git show <旧rev>:<path>` 取旧版查询器，与当前模板**各作为外部副本**跑同一命令 × 预算矩阵，**逐字节比对** stdout + 退出码 → 证明"限额保留"只改内存策略、不改输出 |
| **调用计数插桩** | 加载查询器后包装 `graph_data` / `manifest` 计数，验证跨记录复用是否按预期发生 |
| **预算精确性** | 校验 `remaining_results + len(results)` 恒定；保留峰值 ≤ limit；与直接解析 `20_Evidence/*.json` 的独立计数交叉比对 |
| **快照 diff 造副本** | 改 `pos_x`（`layout_only`）→ 改引脚默认值 → 删边 → 自比对，四类全部命中断言 |
| **哈希一致性** | 比对 `Resources/BlueprintExport/` 模板与包内副本。**不变式：两者必须一致**（`.gitattributes` 固定 `*.py`/`*.md` 为 `eol=lf`）。**不要记具体哈希值**，它随每次改动变化 |
| **全量静态校验** | 脚本遍历全部包：必需文件齐备性、`features` 一致性、逐图 `logic_sha1`/`evidence_sha1`、包内查询器/契约 vs 插件模板 SHA1、换行符、索引 ↔ 目录 1:1 |
| **包内查询器实跑** | 在真实产物上执行全部子命令 + 预算 / 快照 / 身份边界 |
| **跨资产调用闭环** | 逐图跑 `deps` 找跨资产目标 → 再用 `impact --target` 反查调用者，要求两端命中 |
| **规模与耗时** | 全库 `deps` 普查（577 图，12 并发）约 80 s；全库 `impact --target`（114 包 / 694 图）约 2 s；`outline` 大图（75 图）亚秒级 |

| **预算与边界** | envelope **零越界**（多命令 × 多档预算）；非法预算值干净报错（无 traceback）；遍历 `--depth` 单调增长并收敛 |

## 10. 验证边界

**本机可复现**：114 个导出包 / 694 图 / 10864 节点 + 根目录 `00_INDEX.json`；上述差分、插桩、预算、diff、破坏性验证与全量静态校验，均在包内查询器上独立复现。
