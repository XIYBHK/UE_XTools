# 资产移动与按类型归类

内容浏览器选中资产，右键选择 **扁平移动资产及依赖...**，在 UE 原生内容目录树中选择目标。可右键目录使用原生 **新建文件夹**，例如在项目 Content 下建立 Gathered；底层目标路径对应 `/Game/Gathered`。未选择有效目录时不能执行。工具先检查依赖和名称冲突，再显示资产数量及目标供确认。编辑器蓝图也可调用 **扁平移动资产及依赖** 或 **扁平移动选中资产及依赖**，目标参数仍使用 `/Game/...` 包目录路径，并检查返回结果。

目录选择通过 [IContentBrowserSingleton::CreatePathPicker](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Editor/ContentBrowser/IContentBrowserSingleton) 和 [FPathPickerConfig](https://dev.epicgames.com/documentation/unreal-engine/API/Editor/ContentBrowser/FPathPickerConfig) 实现，与 UE 自带目录对话框共用控件。选择器使用 `CustomFolderPermissionList` 仅允许 `/Game`，隐藏类目录及只读目录，回调使用内部包路径而非 `/All/...` 虚拟路径；不使用系统文件夹浏览器或手输磁盘路径。

## 按类型归类移动

右键选择 **按类型移动资产及依赖...**，或调用蓝图节点 **按类型移动资产及依赖** / **按类型移动选中资产及依赖**。它与扁平移动共用依赖收集、预检、引用维护、保存和重定向器修复，仅改变目标路径。原有扁平接口行为保持不变。

分类根据资产真实类及其继承链，不依赖资产名称前缀。下面是目标根目录下的固定目录约定，并非 UE 强制目录标准；目录按实际资产需要创建。

| 类型 | 子目录 |
|---|---|
| 普通蓝图 | `Blueprints` |
| 枚举 / 结构体 | `Blueprints/Enums` / `Blueprints/Structs` |
| 材质 / 材质实例 / 材质函数 | `Materials` / `Materials/Instances` / `Materials/Functions` |
| 纹理及其派生类型 | `Textures` |
| 静态网格 / 骨骼网格 | `Meshes/Static` / `Meshes/Skeletal` |
| 动画 / 动画蓝图 / 骨架 | `Animations` / `Animations/Blueprints` / `Animations/Skeletons` |
| 物理资产 / 物理材质 | `Physics` |
| SoundBase 派生类型、SoundClass、SoundMix | `Audio` |
| Niagara 系统、发射器、脚本及 Cascade 粒子系统 | `FX` |
| Level Sequence | `Cinematics` |
| 数据资产、数据表、曲线表 | `Data` |
| 曲线资产 | `Curves` |
| Widget 蓝图 / 字体、字体面 | `UI` / `UI/Fonts` |
| 其余未覆盖类型 | `Other` |

例如目标 `/Game/Car` 下，蓝图移到 `/Game/Car/Blueprints/BP_Car`，材质实例移到 `/Game/Car/Materials/Instances/MI_Car`，静态网格移到 `/Game/Car/Meshes/Static/SM_Car`。保留资产名称，不保留原目录层级。执行前显示各目标子目录的收集数量（含已在目标的资产）。

冲突按完整目标包路径检查：不同分类目录可有同名资产；默认模式下同一分类目录内同名、或目标已经被其他资产/重定向器占用时，整批拒绝，不覆盖、不自动改名。蓝图还提供显式“自动改名冲突”入口：按源包名字典序稳定分配 `_01`、`_02` 后缀，检查批内目标、已有资产、重定向器和磁盘包；原路径与目标相同的资产仍跳过。已在正确分类目录的资产跳过，重复执行不会创建嵌套分类目录。

## 蓝图来源与语义

参考 `BP_AutoCollision` 导出中的 `Btn_GatherAndMove`：清空收集列表和队列，从选择资产的包名出发，循环读取 Asset Registry 包依赖，只将未访问的 `/Game/` 包入队，加载资产后构造 `FAssetRenameData`，用同一个目标目录和原名一次性调用 `RenameAssets`。

依赖选项包含硬引用、软引用、游戏和编辑器专用包引用；不包含 searchable names 或 management 引用。不是递归移动整个文件夹，也不收集反向引用者。项目内共享材质、纹理等依赖同样会移动；引擎和插件内容保持原位。

导出的蓝图没有显式 Fixup 调用，没有检查 `RenameAssets` 返回值，且再次点击时没有清空 `RenameDataArray`。C++ 使用每次调用独立的局部数组和集合，修复这些边界。

## 引擎做法与实现

- [Asset Registry GetDependencies](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/AssetRegistry/IAssetRegistry/GetDependencies) 读取磁盘依赖。源资产须先保存；每个包查询前同步扫描对应文件，避免刚保存或刚重命名时依赖索引尚未更新。
- 扁平计划在任何移动前检查目录、包类型、加载状态、同批名称冲突和已存在的目标包（包含重定向器）。默认保持资产原名并在冲突时整批拒绝；勾选自动改名后按稳定顺序追加后缀，仍不覆盖已有包。
- 使用 [IAssetTools::RenameAssets](https://dev.epicgames.com/documentation/unreal-engine/API/Developer/AssetTools/IAssetTools) 批量完成移动。UE 自带流程负责检出、引用更新、蓝图生成类路径处理、保存和重定向器创建；不使用操作系统文件移动或裸 `UObject::Rename`。
- 逐项核实资产的实际目标包、磁盘存在及 dirty 状态。引擎执行阶段可能部分成功，返回结果如实报告，不用 `FScopedTransaction` 承诺磁盘移动可撤销。
- 完成前再次检查本次移动包和已知引用包的 dirty 状态。原生重命名/修复 API 并不向调用者返回全部引用包保存失败；关联包仍有未保存修改时，返回未全部完成及包路径，不自动重试保存用户修改。
- 仅把本次成功移动留下的重定向器交给 [FixupReferencers](https://dev.epicgames.com/documentation/unreal-engine/API/Developer/AssetTools/IAssetTools/FixupReferencers)。[Epic 重定向器说明](https://dev.epicgames.com/documentation/unreal-engine/asset-redirectors-in-unreal-engine)要求引用包重存成功才能删除重定向器。保存失败时保留重定向器；修复后仍存在的路径单独返回，不强删资产或源目录。

## 边界

只支持 `/Game` 内普通单资产包。直接选中 `/Engine` 或任意插件挂载目录中的资产时，跳过并保留原位；混选继续处理项目资产，预览和结果列出跳过路径及原因。全选外部资产时提示没有可移动的项目资产，不报告移动成功。蓝图结果 `SkippedExternalAssets` 返回去重后的外部资产路径，独立于表示已在目标目录数量的 `SkippedCount`；目标目录同样禁止使用这些位置。项目资产的引擎/插件依赖保留原路径，不纳入移动或继续遍历其依赖链，不会仅因为引用了引擎材质而阻止项目资产移动。UI 选择、依赖收集和执行前校验均限制在 `/Game`，蓝图调用也不能绕过限制。

地图、World Partition 外部 Actor/对象包、未保存或有未保存修改的项目依赖会阻止执行。已有重定向器可作为依赖链继续遍历，但不作为普通资产移动；显式选中重定向器会报错。

引用修复覆盖引擎能识别的序列化 UObject 和 SoftObjectPath 引用。配置文件、代码或任意字符串中的手写路径不属于可保证自动更新的引用。修复可能出现引擎的检出或诊断窗口；无法检出或保存时保留重定向器并报告，不能将“无报错”视为任意项目下零重定向器的保证。

UE 5.4+ 的原生 Fixup 即使指定删除模式，也会显示“重定向器更新报告”，需要在报告中执行删除未引用重定向器。无界面或禁止弹窗的脚本模式不能运行该报告；此时本工具保留重定向器，返回未全部完成及待修复路径，避免引擎模态窗口断言。可在普通编辑器内容浏览器中完成后续修复。参见 [Epic UE-389775](https://issues.unrealengine.com/issue/UE-389775)。

## 验证

### 官方流程核验（2026-09-07）

已对照本机 UE 5.3、5.7 的 `AssetRenameManager.cpp`、UE 5.7 的 `AssetFixUpRedirectors.cpp` 及下列公开资料：

| 官方要求或行为 | 当前实现 |
|---|---|
| [通过编辑器管理资产，避免在文件系统直接移动](https://dev.epicgames.com/documentation/en-us/unreal-engine/working-with-assets-in-unreal-engine) | 所有资产移动统一使用 `IAssetTools::RenameAssets`；分类模式仅改变 `FAssetRenameData` 的目标目录 |
| [Fixup 必须重存引用包，成功后才能删除重定向器](https://dev.epicgames.com/documentation/unreal-engine/asset-redirectors-in-unreal-engine) | 使用原生 `FixupReferencers`，由引擎处理引用包加载、软路径更新、检出、保存及删除资格；不直接删除旧文件 |
| [FixupReferencers 的 checkout 参数只控制检出提示](https://dev.epicgames.com/documentation/unreal-engine/API/Developer/AssetTools/IAssetTools/FixupReferencers?application_version=5.5) | 传入 `true`，保留引擎检出交互，不禁用 Source Control、不强改只读属性 |
| [Epic 社区支持讨论：不能绕过无法检出/写入的失败](https://forums.unrealengine.com/t/renameassets-and-fixupreferencers-hard-coded-source-control-checkout/2673153) | 不绕过失败；逐项报告移动、保存和遗留重定向器状态 |
| [UE-389775：原生 Fixup 报告无法静默运行](https://issues.unrealengine.com/issue/UE-389775) | UE 5.4+ 无界面/脚本场景有重定向器时保留并报告，普通编辑器沿用原生报告；未擅自模拟点击或强删 |

引擎源码同时确认，`RenameAssets` 本身会根据引用情况决定是否需要重定向器，因此成功移动后“没有重定向器”也可能是正确结果。`DeleteFixedUpRedirectors` 不是忽略失败强删的开关。官方提供的无界面批量清理方案是 `ResavePackages -fixupredirects`；本工具不自动启动项目范围的清理任务。

[社区软引用问题讨论](https://forums.unrealengine.com/t/soft-reference-not-updated-after-renaming-asset/478060)缺少一致复现，不能据此推导当前 UE 版本存在同一缺陷；本项目用磁盘资产、软引用、循环依赖和未加载引用包实测。当前不承诺覆盖任意字符串路径、所有插件特殊资产、真实 Perforce 锁定故障或 UE 5.7 原生报告的交互删除；这些不等同于本轮自动化通过的范围。

`OrganizeByType` 使用真实材质实例、父材质和纹理资产验证递归收集、分类优先级、跨分类同名允许、引用保留、重复执行，以及同类同名和已有分类目标拒绝。自定义 DataAsset 派生类验证继承链分类。UE 5.3 验证移动及重定向器修复；UE 5.4+ 无界面环境接受引擎直接完成引用更新且无需重定向器的结果，若仍有重定向器则要求明确报告未完成。
