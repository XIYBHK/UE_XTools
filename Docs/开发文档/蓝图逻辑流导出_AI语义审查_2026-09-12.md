# 蓝图逻辑流导出：面向 AI 的语义审查

日期：2026-09-12。源码基线：`9453bb9943d2ea22a8c0bf73cc486386b5e75f78`。

目标：让 AI 准确理解蓝图如何编写，包括执行关系、数据来源、参数、状态及依赖边界。人类阅读排版不是主要验收标准。

结论：保留当前 C++ 导出器作为基础，优先补齐语义缺项和可解析性，再减少重复上下文。现有 JSON 比 Markdown 更适合承担主要事实输入，但不能称为完整、无损的蓝图语义表示。

进一步的网络与源码对照见[《面向 AI 的蓝图导出架构与表示方案》](蓝图AI导出_方案深度调研_2026-09-12.md)。该报告补充 NodeCode 的反射与分区架构、按需查询方案，并指出 NodeToCode 当前流数据结构的保真限制；下文的局部机制参考不构成对整个插件的采用建议。

## 1. 当前实现与核验范围

入口是 `X_MenuExtensionManager.cpp:460` 的内容浏览器菜单，经 `FX_BlueprintGraphExporter::ExportBlueprints` → `ExportOneBlueprint`，分别生成 JSON 与 Markdown，保存到宿主 `Saved/XTools/BlueprintExports`。

下文导出器行号均指 `Source/X_AssetEditor/Private/BlueprintTools/X_BlueprintGraphExporter.cpp`。

- JSON 聚合（2820–2864）：变量、CDO 默认值、SCS/默认对象组件、组件树、时间轴和当前 Blueprint 的各个图。
- 图快照（1809–1856）：入口、执行可达边、孤立执行节点、未连接执行引脚、全部普通执行/数据边及节点。
- 节点（1762–1795）：GUID、类名、标题、注释、位置、启用状态、节点语义与引脚。
- 引脚（1713–1759）：ID、名称、方向、类型、默认值、对象/文本默认值及连线。
- 已有语义：函数纯度/const/static/latent/RPC 标志（632–647），宏路径、委托、异步工厂和回调引脚，分支、Sequence、Timeline 等。
- Markdown 独立遍历 UObject，使用图内排序、标签与转接点缓存；不要重复建议这些已经存在的优化。
- `Scripts/ue_blueprint_export_flow.py` 是读取 UE 复制文本的另一条工具链，不是上述菜单调用的后端；本次主结论针对 C++ 菜单导出器。

图谱用于定位；覆盖检查发现文件元数据变化、测试宏解析缺口，因此关键结论回到当前源码核验。引擎契约核验使用本机 UE 5.3 源码。

只读检查了一个已有导出：`BP_ceshi.json`，2026-09-11 19:36:58，75,857 字节、13 个节点、2 张图；对应 Markdown 为 3,882 字节。它是历史样本，本轮没有重新导出，也不代表最新源码性能。事件图的 13 条边同时对应 26 条双向 pin 引用，另有 2 条 `exec_chain` 边；这能说明表示重复，不能据此声称某个 token 压缩率。

## 3. 发现与优先级

### P2：引用、const 与拆分引脚关系缺失

`PinTypeToJson`（516–530）及 `PinTypeToString`（188–212）均未输出 `bIsReference`、`bIsConst`；`PinToJson` 未输出 `ParentPin`、`SubPins` 和 `bOrphanedPin`。

引擎证据：UE 5.3 的 `Engine/Source/Runtime/Engine/Classes/EdGraph/EdGraphPin.h:111,115,337,381,384` 明确存在这些字段。函数级 `is_const` 不能代替参数级 const/reference。

触发例：相同类型的值参数和引用参数，或拆分后的结构体输入。AI 仅看导出类型不能可靠判断引用语义，也缺少明确的子引脚归属；不能把所有引用参数都直接解释为必然发生写入。

最小改进：补参数标志、父子 pin ID 和 orphan 状态；保留默认值/连线，不依靠 pin 名称推断层级。测试应断言值/引用、const/可变参数输出可区分，并覆盖拆分结构体及遗留引脚。先在 5.3 验证，再核对 5.4–5.8 API，不把单版本验证说成全版本通过。

### P2：Markdown 不能独立承载 AI 理解所需事实

`AppendGraphMarkdown`（3011–3107）只生成入口、可达执行流、孤立节点和数据连接摘要；数据连接上限为 100。它没有把 JSON 中的完整节点语义、变量和引脚字面值逐项带入。组件属性也只显示前 20 项（2317 起）。

触发例：两个蓝图只有 `PrintString` 的未连接字符串输入不同，图的连接摘要可能相同；超过 100 条数据连接时，后续依赖不会出现在 Markdown。已有截断提示，但它不能补回缺失事实。JSON 的普通边列表没有这个 100 条上限。

最小改进：明确主要 AI 输入，基于同一份结构化快照生成带节点语义/参数的数据包。大图按图或函数分块并提供索引，边界处显式列出外部引用；不得静默丢掉尾部连线。测试覆盖字面值变化和超过 100 条数据边的完整性。

### P2：外部宏和外部实现没有完整性标记

宏实例仅写 `macro_graph` 和 `source_blueprint`（1384–1397）；根导出只调用当前 Blueprint 的 `GetAllGraphs`（2847–2859）。UE 5.3 `Engine/Source/Runtime/Engine/Private/Blueprint.cpp:1834` 遍历本对象持有的图及其子图，并不会递归获取其他蓝图的宏库实现。

触发例：调用用户自定义宏库里的宏。当前文件有调用点和宏路径，却没有外部宏体。调用其他 Blueprint 函数或项目 C++ 实现也有相似的上下文边界。当前蓝图的本地宏/子图不能笼统归为遗漏。

最小改进：先输出依赖清单及 `included / external / unresolved` 状态。只有需要理解的依赖再按需导出；对宏/函数引用去重并限制遍历范围，避免递归抓取整个项目。测试覆盖本地宏、外部宏和无法解析的引用。

### P2：没有结构化的语义覆盖报告

`NodeSemanticToJson`（1459–1481）未匹配时返回空；`NodeToJson`（1780–1783）只在成功时添加 `semantic`。节点基础信息仍保留，但没有区分“只读取拓扑”和“解析了专用语义”，根部也无未知节点清单。

触发例：第三方或项目自定义 K2Node 的行为还依赖节点 UObject 配置，仅靠类名、标题和连线无法完整表达。AI 无法从缺少 `semantic` 判断具体遗漏。

最小改进：增加节点 `semantic_support` 及聚合覆盖信息，给出 unknown/partial 原因；同时保留节点 class path 与原始引脚证据。不要把“有 handler”自动当成语义完整，不要把未匹配的注释节点一律当成错误。测试同时覆盖基础节点、自定义节点和已支持节点。

### 优化：降低结构重复，保持数据边语义

同一条连线出现在两个 pin 的 `linked_to`（1748–1756）、图 `edges`（1834–1838），可达执行边又出现在 `exec_chain`（1828）。`NodeRefToJson`（1511–1527）在边中重复 GUID、标题、类名；语义对象也重复部分 pin 内容。

建议先保留详细导出用于核验，再由同一快照生成 AI 包：节点/pin 定义一次，连线使用短引用；执行边和数据边各保留一份；类型/对象路径可共享字典。省略默认字段必须写清 schema 缺省规则。不能为了变短而混淆 0、false、空字符串、未知值或显式默认值。

不要直接删除所有坐标：若要导出注释框包含关系，应先从空间关系得到分组再省略布局。稳定标识映射也要保留，以便 AI 的回答能定位回原节点。当前 `N0…` 按布局排序分配（1797–1807），只适合单次图内短引用，不适合作为跨次稳定身份。

### 改进：让 AI 明确执行边不是运行时日志

`BuildExecChainJson`（1546–1609）是多入口、队列去重的静态可达边集合，数组顺序不表示真实执行时序。它不是对 latent、循环、Sequence 或异步回调的执行模拟。

当前已导出 `is_latent`、异步工厂、`delegate_output_pins`（988–1005）和委托信息；不应报告为“完全不支持异步”。建议加入简短消费说明，必要时增加可确定的绑定/调用关系，明确动态目标仍未解析。不要把所有异步输出都称为 completion，可能还包括进度、失败、多次广播等。

## 4. 验证与实施建议

现有测试文件 `X_BlueprintGraphExporterTests.cpp` 有两个测试：SemanticClassification 检查四种节点分类及空输入；GraphSnapshot 构造多入口、转接点、共享尾链、环和跨次修改。快照摘要目前是日志输出，不是固定 golden 断言；重复 Markdown 相等也不能证明语义正确。

最小实施顺序：

1. 补 reference/const、split/orphan pin、依赖状态和语义覆盖信息；增加针对这些行为的断言。
2. 从统一快照生成 AI 数据包，去除重复连线/重复描述，保留完整的参数、注释和外部引用。
3. 用固定蓝图验收：AI 能准确回答“哪些输入是常量/引用”“分支条件来自哪里”“回调何时可能发生”“哪些宏体不在输入中”；答案必须指向节点/pin ID。对比精确率、遗漏和所选模型 tokenizer 统计，不能只比较文件字节数。
