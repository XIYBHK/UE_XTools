## 2. 有意思的设计

### 2.1 ⭐ 自建"蓝图标准库"：13 个函数库 / 约 4200 节点

| 库 | 函数 | 节点 | 定位 |
|---|---|---|---|
| **SimpleLib** | 75 | 1672 | 排序全家桶 + 点位生成 + 数组工具 |
| **BFL_05阵型点位** | 8 | 424 | 圆形/环状/球/样条/螺旋阵型 |
| **RandomLib** | 28 | 413 | 随机数（普通 + 流送双轨） |
| **BFL_08不常用节点** | 24 | 363 | 散射旋转、朝向目标、网格体材质 |
| **AdvancedLib** | 16 | 296 | 贝塞尔点、Sin 采样、网格体顶点 |
| **VectorLib** | 14 | 251 | 位置的最近/最远/中间/平均 |
| **BFL_01常用节点** | 25 | 214 | ISM 数组、旋转体运算、面向摄像机 |
| **BFL_04随机数据** | 17 | 182 | 随机数组、正负输出 |
| **BFL_07方向与冲量** | 12 | 169 | 冲量计算（6 种变体） |
| **BFL_10Trace** | 5 | 84 | 多盒体/球体/线/胶囊检测 |
| **BFL_03网格体** | 7 | 67 | 网格体渲染/阻尼/碰撞设置 |
| **BlackMagicLib** | 3 | 30 | GetDefaultObject / 路径转换 / GetWorld |
| **PhysicLib** | 2 | 29 | 物理速度/模拟开关 |

SimpleLib 重头：`快速排序浮点/整数_私有`（各 100 节点、**递归调用自身 3 次**）、`根据坐标排序向量` 76、`在矩形上生成点位` 60、`最近的Actor` 51、`按夹角和距离排序Actor数组` 39，以及 `清除{X}数组中重复值`（6 类型）、`由{索引/距离/值}截取{X}数组`（3×6 组合）。

### 2.2 ⭐⭐ "普通版 / 流送中版"双轨随机 API —— 本语料最聪明的设计

`RandomLib` 几乎每个随机函数都成对出现：`范围内随机向量` / `流送中范围内随机向量`、`绝对值范围内随机浮点` / `流送中…`、`范围内随机旋转` / `流送中…`、`范围内随机线性冲量` / `流送中…`、`随机线性颜色` / `流送中随机线性颜色`。

实现差异在调用点可直接验证：

```text
# 普通版 G0001
@N3: expr "KismetMathLibrary:RandomFloatInRange"(Min=@N2["X"], Max=@N6["X"])

# 流送中版 G0002 —— 多一个 RandomStream 引用参数，用 FromStream 变体
@N2: expr "KismetMathLibrary:RandomFloatInRangeFromStream"(
       ref const "Stream"=@N0["Seed"], Min=@N3["X"], Max=@N6["X"])
```

**设计意图**：把 `FRandomStream` 提升为一等公民 → 随机**可复现**（同 seed 同结果），服务于确定性回放、联机同步、程序化生成。配套 `F_固定随机流送` / `随机流送` / `坐标流送`。全库 `RandomFloatInRangeFromStream` 被调 **18 次** → 真在用，不是摆设。

### 2.3 接口驱动的受击 / 交互解耦

5 个 `Interface` 资产（子弹受击 / 范围检测 / 资源交互 / 背包交互 / 功能接口）+ `DoesImplementInterface` 反复调用。`单体子弹:G0004` 的 Tick 路径**先问接口再决定是否命中**：子弹不硬编码"我打谁"，而是问目标"你实现了受击接口吗" —— 干净的扩展点。

### 2.4 组件化的表现层

| 组件 | 节点 | 跨包被调 | 职责 |
|---|---|---|---|
| `BPC_网格体反馈组件` | 344 | **11** | 闪红 / 扣血 / 血条 / 伤害数字 / 缩放 |
| `BPC_静态网格体组件` | 82 | 5 | 自转 / 浮动 / 缩放 / 闪红 / 受击 |
| `BPC_Q版金币组件` | 61 | — | 金币生成与吸附 |

把"挨打长什么样"抽成组件，任何敌人挂上即可 —— **11 处跨包调用**是直接证据。

### 2.5 状态机式角色 AI

`BP_丧尸父类:G0019`（287 logic / **24 入口**）是完整 AI 状态机（纯待机/游荡/巡逻/检测/寻主/行走/样条行走/受击/击退/死亡变体…）。**Tick 里只做分派**：

```text
@N1: event "ReceiveTick"() -> @N2: branch("角色死亡")
        then -> (跳过)   else -> @N3: call "F_角色移动"(方向, 旋转)
```

每帧只判一个 bool 再转交 —— 权威状态留蓝图，重活推给函数。同一结构在 `BP_跑酷主角父类:G0009`、`BP_割草主角父类:G0007` 复用（死亡/碰撞处理几乎一样）。

### 2.6 曲线弹道与样条工具链

`BP_子弹:G0002`（`BuildBezierMissileControlPoints` + `RandomFloatInRange` → 贝塞尔导弹）、`BP_Launcher_Beam:G0006`（`SetBeamTargetPoint` + 自研 `SearchEnemy`）、`样条线生长`（Timeline 驱动 `SetPlayRate`）、`抛物线:G0005`（`GetLocationAtSplinePoint`）、`BP_ThirdPersonCharacter:G0002`（EnhancedInput + `SplineFollowLibrary`）。

### 2.7 权重随机 / PRD 与动作驱动状态广播

- `RandomLib:带权重的随机整数/对象数组`（各 42 节点）+ 专用测试图 —— **与插件 `RandomShuffles` 模块的 PRD 伪随机呼应**，项目在"随机公平性"上很认真。
- 148 个 `custom_event` 命名强约定：`CE_` 前缀（`CE_初始化`/`CE_旋转`/`CE_掉落`/`CE_飞向目标`/`CE_扣血`…）、`事件F`/`F_` 函数型入口。**`CE_XXX属性设置` + `CE_XXX` 成对**是自造的**参数化事件模式**（先配参数再触发），在 `BP_背包资源Base` 密集出现 8 组。

## 3. 适合转 C++ 的候选（按 ROI 排序）

**判定**：纯逻辑、无资产引用、调用热度、运行频率（Tick / 构造期）、算法密度、跨包重复。

### 3.1 第一梯队：函数库整体重写 —— 零风险、收益最大

| 候选 | 规模 | 为什么转 | 预期收益 |
|---|---|---|---|
| **`SimpleLib` 全 75 函数** | 1672 | 纯算法、零资产依赖；快排各 **100 节点且递归 3 次** —— 蓝图跑递归快排是典型反模式 | 排序/截取/去重调用点一次提速，图面大幅缩小 |
| **`RandomLib` 28 函数** | 413 | 薄封装（`BreakVector` + 3×`RandomFloatInRange` + `MakeVector`） | 合并双轨为 `FRandomStream&` 重载 |
| **`AdvancedLib` 16 函数** | 296 | 含 `获取静态网格体顶点位置` —— **顶点遍历在蓝图 VM 里极慢** | 顶点/贝塞尔/Sin 显著提速 |
| **`VectorLib` 14 函数** | 251 | 最近/最远/中间/平均 —— 纯数学 | 简单直接 |
| **`BFL_04随机数据` 17 函数** | 182 | 全库被调最密集的蓝图库之一 | 热路径 |
| **`BFL_07方向与冲量` 12 函数** | 169 | 冲量计算 6 变体，全数学 | 简单直接 |
| **`BFL_03网格体` / `BFL_10Trace`** | 67 / 84 | 网格体设置是样板；4 种形状检测可写成一个 C++ 模板 | 样板代码归零 |

> 转换方式：新建继承 `UBlueprintFunctionLibrary` 的类，**保持函数签名与 `DisplayName` 完全不变**，蓝图调用点无需改动即可生效。

### 3.2 第二梯队：性能敏感（Tick / 构造期 / 大量实例）

| 候选 | 证据 | 症结 |
|---|---|---|
| **`BP_背包:G0008`** | **355 logic（全库最大单图）** + Tick + 9× timer 句柄 + 27 自定义事件 | 状态机 + 定时器管理放蓝图，每帧 BP 调度 |
| **`BP_丧尸父类:G0019`** | 287 logic / 24 入口 / Tick | AI 状态机；**每个敌人一份实例** → 转基类 + 数据驱动 |
| **`BP_背包资源Base:G0008`** | 260 logic / **8 Timeline** / Spawn / 物理 / 样条 | 时间轴 + 物理 + 飞行三合一 |
| **`BPC_网格体反馈组件:G0005`** | 185 logic / **跨包被调 11 次** / DMID 每帧设参 | 表现层组件最自然的 C++ 化对象 |
| **`单体子弹:G0004`** | 81 logic / **跨包被调 23 次** / 接口判定 5 次 | **子弹是数量级最大的实例群**，每发都跑 BP VM |
| **`BP_Q版金币:G0002`** | 115 logic / Tick / 4 Timeline | 掉落物同屏量大，Tick 轮询最吃亏 |
| `BP_LightStudio:G0001` | **构造脚本 155 logic** | 构造脚本每实例每次都执行；⚠️ 属 `/Game/StarterContent/` 示例，优先级下调 |

### 3.3 第三梯队：合并去重（抽公共组件）

| 重复模式 | 证据 | 建议 |
|---|---|---|
| "飞到目标 / 添加力 / 缩放出现"**两套** | `BP_背包:G0008` 与 `BP_背包资源Base:G0008` 各一整套同名事件 | 抽 `UAttractFlyComponent` |
| 死亡/碰撞处理三处雷同 | 丧尸 / 跑酷 / 割草父类都是 `SetCollisionEnabled` + `StopMovementImmediately` + `K2_DestroyActor` | 抽 `UDeathHandlerComponent` 或角色基类 |
| 多形状 Trace | `BFL_10Trace` 盒/球/线/胶囊结构一致 | 一个模板函数 |
| 父级/附着查询 | `AdvancedLib` 最高父级(32+15) / 所有子Actor(25) / 父子关系(9) | C++ 直接循环 |
| 数组转换矩阵 | `SimpleLib` 浮点↔整数↔字符串↔向量互转 10+ 函数 | 可变模板 |

### 3.4 已在进行中（方向正确）

蓝图已在调用 **XTools 插件自身 C++**：`XToolsLibrary:BuildBezierMissileControlPoints`、`SplineFollowLibrary:CalculateInitialSplineRightOffset`、`MathExtensionsLibrary:ApplyScaleCurveAmplitude`、`AxisLockerComponent:PushLockState` —— **BP→C++ 通道本来就是通的**。

### 3.5 不建议转 C++

| 类型 | 例子 | 理由 |
|---|---|---|
| 纯 UI 控件绑定 | `血条控件`、`BP_UI动画控件` | UMG 蓝图设计器驱动，转 C++ 反失可编辑性 |
| 示例/测试资产 | `BP_LightStudio`、`BP_锁轴测试`、`权重数组测试`、`NewBlueprint` | 非产品路径 |
| 纯接口声明 | 5 个 Interface 蓝图 | 已是最轻形态 |
| 数据资产 | `BP_背包资源Base` 的 `PrimaryDataAsset` ×3 | 数据应留编辑器，只把行为转 C++ |

## 4. 结论速览

| 问题 | 结论 |
|---|---|
| **最值得转 C++** | ① `SimpleLib`(1672) ② `RandomLib`(413) ③ `AdvancedLib`(296) ④ `VectorLib`(251) —— **13 库共 ~4200 节点，纯逻辑、零资产依赖、签名可原地保持**，最高性价比 |
| **最该查性能** | `BP_背包:G0008`(355 + Tick + 9 timer)、`BP_丧尸父类:G0019`(287 + Tick)、`单体子弹:G0004`(跨包 23) |
| **最聪明的设计** | 普通版 / 流送版**双轨随机 API**（可复现随机） |
| **最系统的设计** | 13 库构成的**自建蓝图标准库** + 组件化表现层 + 接口驱动受击 |
| **最该抽公共件** | "飞到目标/添加力/缩放" 在 `BP_背包` 与 `BP_背包资源Base` 各一套 |

## 5. 方法与边界

- **数据来源**：`20_Evidence/*.json` 的 `semantic` + `10_Logic/*.pseudo.md` + `00_Asset.json`。
- **口径**：694 图 = 577 资产图 + 117 宏图；"logic 节点"已剔除 `comment`/`reroute`/`tunnel_*` 装饰节点。
- **热度定义**：`resolved_function` 出现次数 —— **静态调用点计数**，非运行期次数。
- **未做**：未运行蓝图、未启动 UE、**未实测性能**；"预期收益"是推断，落地前需实测。
- **误读防护**：`_私有` 是作者命名习惯（非访问级别）；`流送` = `RandomStream`，非流式加载。
