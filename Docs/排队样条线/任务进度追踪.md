# 排队样条线任务进度追踪

## 设计原则

- C++ 负责核心状态、调度、算法和鲁棒性。
- 蓝图只做配置、表现、接线和少量业务事件。
- 队列关系不使用 `前方actor / 后方actor` 作为核心模型。
- 单个成员不递归驱动其他成员。
- 随机、排序、补位、暂停恢复都必须可复现、可调试。

## 当前目标

实现一个“排队样条线”系统，支持：

1. 真实的左右交错和轻微随机偏移。
2. 从入口进入或按样条比例预填充。
3. 动态入队、离队、补位。
4. 接入 `AI MoveTo`、`AddMovementInput` 或项目自定义移动。
5. 蓝图可调用、可配置、可调试。

## 总体架构

### 1. Runtime 核心模块

建议新建独立模块 `QueueSpline`，不要放进 `BlueprintExtensionsRuntime`。

推荐依赖：

- `Core`
- `CoreUObject`
- `Engine`
- `XToolsCore`

可选依赖：

- `ObjectPool`

### 2. 核心组件

#### `UQueueSplineComponent`

队列实例的权威控制器。

职责：

- 持有队列成员。
- 生成初始布局 Transform。
- 保存成员的样条距离游标并生成短前视目标。
- 处理入队、离队、补位、暂停、恢复、中断。
- 广播状态变化。

#### `UQueueSplineMovementComponent`

挂在角色/AI 身上，负责执行目标。

职责：

- 接收队列目标。
- 提供简单的 `DirectInterp` / `AddMovementInput` 适配。
- 只管“怎么动”，不管“去哪里”。
- 广播移动开始、到达、停止事件，供角色蓝图驱动表现。

`DirectInterp` 只适合展示验证或不需要碰撞/导航的 Actor。正式 Character/AI 应由 `CharacterMovementComponent`、`AIController`、Behavior Tree 或 StateTree 执行真实移动。

#### `UQueueSplineSubsystem`

轻量世界级登记表，当前只负责：

- 注册和注销队列组件。
- 查询当前世界中的有效队列数量。
- 清理无效弱引用。

它不更新成员、不执行移动、不处理售货台业务。只有出现跨队列查询或转移的明确需求时才扩展。

#### 角色蓝图 / AnimBP

负责业务和表现，不进入队列核心组件：

- 根据移动事件切换走路、等待、服务、离开动画。
- 根据目标中的 `Phase` 区分 `Queued`、`Serving`、`Exiting`。
- 处理售货台交互、付款条件、音效和 UI。

### 3. 数据结构

#### `FQueueSplineMemberHandle`

成员句柄，不暴露稳定数组下标。

#### `FQueueSplineMemberState`

成员运行时状态：

- 句柄
- 弱引用 Actor
- 当前槽位索引（只表示队列顺序，不是移动完成点）
- 目标距离
- 当前偏移
- 是否到达样条终点
- 成员阶段

#### `FQueueSplineSlot`

槽位结果：

- 索引
- 样条距离
- 世界位置
- 世界旋转
- 移动方向

#### `FQueueSplineSettings`

排队参数：

- 间距
- 前视距离
- 到达容差
- 起始方式
- 预填充比例
- 左右交错
- 偏移量
- 随机种子

## 现有可复用内容

### `QueueSplineLibrary`

当前已有的 `UQueueSplineLibrary` 只作为几何算法工具：

- 生成槽位
- 计算单槽位
- 偏移回归
- 配置校验

它是正确方向上的算法底座，但不是最终运行时架构。

### `SplineFollowLibrary`

可复用：

- 样条距离
- 右向量
- 前视目标
- 速度补偿

不复用：

- 单 Actor 跟随状态作为队列核心

### `SplineMovement`

可复用为移动适配器，但不作为每个成员的核心调度器。

### `ObjectPool`

仅用于成员 Spawn / 回收，不参与队列排序。

### `FormationSystem`

只借鉴“分配结果 + 生命周期回调”思路，不直接复用阵型组件。

## 推荐蓝图边界

蓝图只做这些事：

- 创建/放置队列管理 Actor。
- 配置 `QueueSplineComponent`。
- Spawn 或对象池取出成员。
- 注册/移除成员。
- 读取目标并执行移动。
- 触发动画、音效、UI。

蓝图不要做这些事：

- 维护成员前后链。
- 递归调用其他成员事件。
- 自己拼队列拓扑。
- 在 Tick 里重建大逻辑。

## 初版蓝图工作流

1. 放置一个 `BP_QueueSplineManager`。
2. 添加 `SplineComponent`。
3. 添加 `QueueSplineComponent`。
4. 配好样条、间距、偏移和填充模式。
5. Spawn 角色或从对象池取出角色。
6. 调用 `RegisterQueueMember`。
7. 读取成员目标并驱动移动组件。

注册成员前必须保证 `SplineComponent` 有效、至少有两个样条点且 `Spacing > 0`；否则 `RegisterQueueMember` 返回失败，不会生成有效句柄。

## 详细蓝图接线

### A. 管理器蓝图 `BP_QueueSplineManager`

#### 组件

- `SplineComponent`
- `QueueSplineComponent`

#### 变量

- `QueueSplineComponent` 引用
- `SplineComponent` 引用
- `SpawnedMembers`：Actor 数组
- `MemberHandles`：`FQueueSplineMemberHandle` 数组
- `bAutoRegisterOnBeginPlay`

#### BeginPlay 接线

```text
Event BeginPlay
 -> Set QueueSplineComponent.SplineComponent = SplineComponent
 -> Set QueueSplineComponent.Settings
 -> Set QueueSplineComponent.bAutoUpdate = true
 -> Set QueueSplineComponent.bAutoPushToMovementComponent = true
 -> ForEach SpawnedMembers
      -> RegisterQueueMember
      -> Add OutHandle 到 MemberHandles
```

如果成员是临时 Spawn 的，顺序改成：

```text
Event BeginPlay
 -> Spawn / ObjectPool Acquire
 -> Add 到 SpawnedMembers
 -> RegisterQueueMember
 -> 保存 OutHandle
```

#### 成员生成后接线

```text
Spawn Actor
 -> Add 到 SpawnedMembers
 -> 取出 Actor 上的 QueueSplineMovementComponent
 -> RegisterQueueMember
 -> 保存 Handle
```

如果你想让成员出生后先摆一下再入队：

```text
Spawn Actor
 -> 临时播放出生动画
 -> RegisterQueueMember
 -> 等待一小段时间
 -> 交给 QueueSplineComponent 更新目标
```

#### 自动推送模式

勾选 `QueueSplineComponent.bAutoPushToMovementComponent` 后，管理器基本不需要再手动送目标。  
队列组件会在 `UpdateQueueTargets` 时直接把目标推到成员身上的 `QueueSplineMovementComponent`。

#### 手动推送模式

如果你不想让队列组件自动推送：

```text
QueueSplineComponent.OnMemberTargetUpdated
 -> 从 Handle 找到对应成员 Actor
 -> Actor 上 GetComponentByClass(QueueSplineMovementComponent)
 -> SetQueueMoveTarget
```

这条线适合你想在中间插自己的逻辑，比如：

```text
目标点到达前先转身
-> 再播放待机动画
-> 再发移动
```

### B. 成员蓝图 `BP_QueueSplineMember`

#### 组件

- `QueueSplineMovementComponent`

#### 变量

- `QueueHandle`：`FQueueSplineMemberHandle`
- `QueueOwner`：`QueueSplineComponent` 引用
- `bUseManualTargetPull`

#### 注册后接线

```text
BeginPlay
 -> 如果已知 QueueOwner
      -> RegisterQueueMember
      -> 保存 QueueHandle
```

如果成员是由管理器 Spawn 出来的，通常由管理器统一注册，不建议成员自己乱注册。

#### 自动接收目标

如果你开启自动推送：

```text
QueueSplineComponent.bAutoPushToMovementComponent = true
 -> C++ 自动调用成员的 QueueSplineMovementComponent.SetQueueMoveTarget
```

成员蓝图不用再 Tick 查目标。

自动推送模式下，注册成员时会让成员移动组件等待队列组件 Tick，确保本帧先产生目标，再执行移动。运行时切换 `bAutoPushToMovementComponent` 后重新注册成员，或使用手动目标模式。

#### 移动阶段与动画接线

在 `BP_QueueSplineMember` 中选中 `QueueSplineMovementComponent`，添加以下组件事件：

```text
OnQueueMoveStarted(Target)
 -> Break FQueueSplineMoveTarget
 -> 保存 Phase
 -> bQueueMoving = true
 -> AnimBP 进入移动状态

OnQueueMoveArrived(Target)
 -> Break FQueueSplineMoveTarget
 -> 保存 Phase
 -> bQueueMoving = false
 -> 按 Phase 进入排队等待 / 服务等待 / 离开完成表现

OnQueueMoveStopped(Target)
 -> bQueueMoving = false
 -> 清理移动表现
```

事件是状态边沿事件，不会随 `OnMemberTargetUpdated` 每帧重复触发：

- 首次收到有效目标：未到达触发 `Started`，已在目标处触发 `Arrived`。
- 自动 `AddMovementInput` 模式下，同一目标到达后会保持锁存，不会因越过容差重新触发 `Started`。
- 阶段或前视目标位置变化后解除锁存并继续移动。
- 从未到达变为已到达：触发 `Arrived`。
- 调用 `StopQueueMovement`、传入无效目标或替换为其他成员句柄：触发 `Stopped`。
- 自动推送模式下，成员被移除或清空队列时会清除目标并触发 `Stopped`。到达路径终点不会自动注销，蓝图可在 `OnQueueMoveArrived` 中销毁角色或调用 `UnregisterQueueMember`。

AnimBP 只读取角色蓝图保存的 `bQueueMoving` 和 `Phase`，不要在 AnimBP 中维护队列顺序或调用排队调度。

#### 自定义移动逻辑

需要用蓝图 `AI MoveTo` 或项目自己的移动流程时，关闭自动推送：

```text
QueueSplineComponent.bAutoPushToMovementComponent = false

QueueSplineComponent.OnMemberTargetUpdated(Handle, Target)
 -> GetQueueMemberState(Handle)
 -> 从 MemberState 取得 Actor
 -> 仅当槽位 / Phase / 目标位置发生有效变化时
 -> 在 AIController / BehaviorTree 中执行 AI MoveTo
```

`OnMemberTargetUpdated` 是高频目标输出事件，不要直接在它上面每帧重新调用 `AI MoveTo`。AI 移动应使用 NavMesh 和合理的 Acceptable Radius；如果必须严格沿样条行走，应使用样条距离游标和前视目标分段移动。

自定义移动完成后，可把最新 `Target` 送入 `QueueSplineMovementComponent.SetQueueMoveTarget`，继续复用统一的阶段事件；也可以完全由角色蓝图维护自己的移动表现状态。

#### 手动拉取目标

如果你希望成员自己拉取目标：

```text
Event Tick
 -> Branch(bUseManualTargetPull)
 -> QueueOwner.GetQueueMoveTarget(QueueHandle)
 -> Branch(ReturnValue)
 -> QueueSplineMovementComponent.SetQueueMoveTarget
```

这适合你想把队列更新频率和成员移动频率分开。

### C. 直接插值移动

成员蓝图里把 `QueueSplineMovementComponent.MovementMode` 设成 `DirectInterp`。

接线：

```text
QueueSplineMovementComponent
 -> bAutoMove = true
 -> MovementMode = DirectInterp
 -> DirectInterpSpeed / RotationInterpSpeed 调整
```

这种模式最省事，适合先看队列形态。

### D. AddMovementInput 移动

适合 Character/Pawn：

```text
QueueSplineMovementComponent
 -> bAutoMove = true
 -> MovementMode = AddMovementInput
 -> MovementInputScale 调整
 -> bAutoSpawnDefaultController = true
```

蓝图侧不需要自己写路径逻辑，只要持续喂目标方向。

自动模式在首次进入路径终点的到达容差时会停止继续输入、清除待处理输入并立即停止 Pawn Movement 的残余速度。同一终点保持到达锁存，不会因越过容差反复触发事件。

中途 Box 触发器停靠由角色自己的 `QueueSplineMovementComponent` 控制：

```text
Box OnComponentBeginOverlap
 -> Cast 排队角色
 -> Get QueueSplineMovementComponent
 -> SetQueueMovementPaused(true)

业务条件满足 / Box EndOverlap / 服务完成
 -> SetQueueMovementPaused(false)
```

角色已注册到队列时，`SetQueueMovementPaused(true)` 会把停靠状态提交给 `QueueSplineComponent`，暂停该成员和所有注册顺序位于其后的成员；前方成员不受影响。解除时会重新计算全部停靠状态，因此后方成员若有自己的停靠请求，仍保持暂停。

暂停请求只立即覆盖请求发生时已经注册的成员。暂停期间新生成并注册的成员会继续沿样条补位；当前一位已经暂停且双方样条距离进入 `间距 + 到达容差` 时，该成员才暂停，因此同一入口批量生成的成员会逐个补到队尾，不会在出生点互相冻结。`设置排队暂停(true)` 是全队硬暂停，仍会立即暂停包含后加入成员在内的所有成员，不适合售货台停靠传播。

组件会保留当前前视目标。暂停期间队列仍可刷新目标，但相关角色不执行移动；恢复后继续沿样条前进。传播顺序以注册顺序为准，预填充时必须按 `GenerateInitialSpawnTransforms` 返回数组的顺序生成并注册成员。

`StopQueueMovement` 与暂停不同：它会清除当前移动目标并触发 `OnQueueMoveStopped`。在自动推送模式下，队列组件下一帧可能重新下发目标，因此不要用它实现触发器等待；它适合成员注销、清空队列或显式取消当前移动任务。

地面队列的到达距离和移动方向按 XY 平面计算，不包含 Character 胶囊中心与地面样条之间的 Z 高差。样条目标仍保留原始 Z，供直接插值和蓝图表现读取。

如果成员是运行时 Spawn 出来的 `Character`，推荐二选一：

- 在角色 Class Defaults 中把 `AutoPossessAI` 设为 `PlacedInWorldOrSpawned`。
- 保持 `QueueSplineMovementComponent.bAutoSpawnDefaultController = true`，由组件在需要输入移动时补一次默认 Controller。

### E. AI MoveTo 接法

当前第一版没有把 `AI MoveTo` 直接做进核心组件。蓝图里可以这样接：

```text
QueueSplineComponent.OnMemberTargetUpdated
 -> 比较上次已发送的 SlotIndex / Phase / TargetLocation
 -> 变化超过阈值时
 -> Break FQueueSplineMoveTarget
 -> 获取 AIController
 -> Move To Location(Target.Slot.TargetLocation)
```

不要把 `DirectInterp` 和 CharacterMovement、根运动或网络位置复制同时作为正式移动方案使用。自动 `AddMovementInput` 模式调用 `StopQueueMovement` 时会清除待处理输入并停止 Pawn Movement 的残余速度；它不会中断 AIController 的其他移动任务，手动目标和 `DirectInterp` 模式也不接管外部移动系统。

如果你想每个成员自己处理：

```text
QueueSplineComponent.GetQueueMoveTarget
 -> Break FQueueSplineMoveTarget
 -> AIController.MoveToLocation
```

### F. 入口进入 / 预填充

#### 从入口进入

```text
QueueSplineComponent.Settings.FillMode = FromStart
QueueSplineComponent.Settings.EntryDistance = 0
QueueSplineComponent.Settings.bHeadTowardSplineEnd = true
```

接线。`GenerateInitialSpawnTransforms` 在此模式只返回一个入口 Transform，避免多个角色同时生成在同一点：

```text
CE_生成（独立事件）
 -> GenerateInitialSpawnTransforms(Count = 1)
 -> Get(0)
 -> Spawn Actor（使用 Transform）
 -> RegisterQueueMember
 -> 成员从入口沿样条持续移动
```

#### 按比例预填充

```text
QueueSplineComponent.Settings.FillMode = PreFilledRatio
QueueSplineComponent.Settings.FillRatio = 0.5
```

接线。`GenerateInitialSpawnTransforms` 返回队头到队尾的初始 Transform 数组：

```text
CE_生成（独立事件）
 -> GenerateInitialSpawnTransforms(Count)
 -> ForEachLoop
      -> Spawn Actor（使用 Array Element Transform）
      -> RegisterQueueMember
      -> 保存 Handle
 -> 生成后的成员沿样条持续移动
```

`FillMode` 只影响初始生成位置，不再决定运行时移动目标。每个成员运行时追踪“当前样条距离 + 路径前视距离”；前视点到达末端时仍不算完成，只有成员本体进入路径终点的 `ArrivalTolerance` 才触发 `OnQueueMoveArrived`。

### G. 运行时入队 / 离队

#### 新成员入队

```text
Spawn Actor
 -> RegisterQueueMember
 -> 保存 Handle
 -> Set QueueOwner
 -> QueueSplineComponent.UpdateQueueTargets
```

#### 成员离队

```text
按 Handle
 -> UnregisterQueueMember
 -> 如果要补位
      -> RebuildQueueSlots
      -> UpdateQueueTargets
```

### H. 推荐最小测试蓝图

先做一个只验证形状的版本：

```text
BP_QueueSplineManager
 -> 10 个成员
 -> 入口进入
 -> 自动推送
 -> DirectInterp
```

你先看这 4 件事：

1. 槽位是不是按样条排开。
2. 左右交错是不是生效。
3. 随机偏移是不是稳定。
4. 成员是否能自然回到目标位。

### I. 售货台服务流程

队列组件维护队列状态，售货台触发器只负责通知，服务条件仍由蓝图业务决定：

```text
售货台触发器 OnComponentBeginOverlap
 -> Cast 到排队成员
 -> QueueSplineComponent.NotifyMemberReachedService(成员Actor)
```

通知成功后，成员进入 `Serving`。服务点是否允许继续前进由蓝图 Box 触发器暂停控制，队列组件不把服务点当作移动完成点。

```text
服务完成条件（付款完成 / 动画完成 / 计时器完成）
 -> QueueSplineComponent.CompleteCurrentServiceAndExit
```

完成服务后，成员进入 `Exiting`，继续沿样条向路径终点移动。收到 `OnQueueMoveArrived` 后由蓝图注销、回收或销毁成员。

```text
QueueSplineComponent.OnMemberServiceStarted
 -> 播放服务动画 / 显示交互 UI

QueueSplineComponent.OnMemberServiceCompleted
 -> 播放离开动画 / 清理服务状态
```

## 初版功能清单

- 权威队列控制器。
- 成员注册 / 移除。
- 槽位生成 / 重建。
- 左右交错与随机偏移。
- 入口进入 / 预填充。
- 可复现随机。
- 调试绘制。
- 目标查询。

## 明确不采用

- `前方actor / 后方actor` 作为核心模型。

## 蓝图导出诊断

导出工具现在会在 JSON 根对象写入：

- `component_count`
- `components`
- `component_tree`
- `class_defaults`
- `default_object_components`
- `unconnected_exec_pins`

`components` 是扁平列表，适合搜索某个组件是否存在。  
`component_tree` 是 SimpleConstructionScript 父子树，适合检查组件挂载关系。
`class_defaults` 适合看蓝图 CDO 上的 Actor/Character 默认配置。  
`default_object_components` 适合看继承来的原生组件，比如 `CharacterMovement`。  
`unconnected_exec_pins` 适合直接发现“BeginPlay 断线/生成事件没接上”这类问题。

重新导出 `BP_队列管理器` 和 `BP_排队角色` 后，先查：

```text
BP_队列管理器.json
 -> components / component_tree
 -> 是否存在 /Script/QueueSpline.QueueSplineComponent
 -> QueueSplineComponent.SplineComponent 是否指向样条组件
 -> bAutoUpdate 是否 true
 -> bAutoPushToMovementComponent 是否 true

BP_排队角色.json
 -> components / component_tree
 -> 是否存在 /Script/QueueSpline.QueueSplineMovementComponent
 -> bAutoMove 是否 true
 -> MovementMode 是否为 DirectInterp 或 AddMovementInput
```

如果“生成后没有移动”，最小诊断顺序：

1. 管理器是否成功 `RegisterQueueMember`，并保存有效 Handle。
2. 管理器 `QueueSplineComponent.SplineComponent` 是否有效，样条点是否大于等于 2。
3. 成员 Actor 是否真的挂了 `QueueSplineMovementComponent`。
4. 自动推送模式下，管理器的 `bAutoPushToMovementComponent` 是否开启。
5. 移动组件的 `bAutoMove` 是否开启，`MovementMode` 是否不是 `ManualTarget`。
6. 如果用 `AddMovementInput`，成员必须是 Pawn/Character；普通 Actor 先用 `DirectInterp` 验证队列逻辑。
7. 如果 `class_defaults` 里没有 `AutoPossessAI` / `AIControllerClass` 这类默认配置，说明需要再从蓝图类默认对象看。

## 当前确认结果

- `DirectInterp` 模式可移动，说明队列目标、注册和组件更新链路正常。
- `CE_生成` 保持为独立事件，由编辑器手动触发是可行的。
- `AddMovementInput` 模式下，如果成员是 Spawn 出来的 `Character`，要注意 `AutoPossessAI = PlacedInWorld` 不会自动接管新生成对象；需要改成 `PlacedInWorldOrSpawned` 或手动 Possess。
- C++ 已补 `bAutoSpawnDefaultController`，组件会在 `AddMovementInput` 模式下为没有 Controller 的 Pawn 尝试 `SpawnDefaultController()`，失败时只打一条警告。
