# Unreal Engine 命令行编译

本文给出 Windows/PowerShell 下可复用的 Unreal Build Tool 调用方式。项目专用目标和路径应从宿主项目 `.vscode/tasks.json` 或 CI 配置读取，不要把个人机器盘符写进长期文档。

## 1. 参数占位符

| 占位符 | 含义 | 示例形式 |
| --- | --- | --- |
| `<EngineRoot>` | UE 安装根目录 | `C:\Epic\UE_5.3` |
| `<Project>` | `.uproject` 绝对路径 | `C:\Work\Game\Game.uproject` |
| `<ProjectName>` | 不含扩展名的项目名 | `Game` |
| `<Platform>` | 目标平台 | `Win64` |
| `<Configuration>` | 构建配置 | `Development`、`Shipping` |

## 2. PowerShell 安全调用

每个 native 参数作为数组元素传入，避免路径空格和嵌套引号破坏参数边界：

```powershell
$buildExe = '<EngineRoot>\Engine\Build\BatchFiles\Build.bat'
$buildArgs = @(
    '<ProjectName>Editor'
    'Win64'
    'Development'
    '-Project=<Project>'
    '-NoHotReloadFromIDE'
)

& $buildExe @buildArgs
$buildExitCode = $LASTEXITCODE
if ($buildExitCode -ne 0) {
    throw "UE build failed with exit code $buildExitCode"
}
```

不要：

- 把整条命令拼成一个字符串；
- 使用 `Invoke-Expression`；
- 为调用 `Build.bat` 再套一层 `cmd.exe /c`；
- 用 Live Coding 成功替代正式 Target 构建。

## 3. 常用目标

### Editor Development

验证 UHT、Editor 模块、UncookedOnly 模块和自动化测试编译：

```powershell
$buildArgs = @(
    '<ProjectName>Editor'
    'Win64'
    'Development'
    '-Project=<Project>'
    '-NoHotReloadFromIDE'
)
```

### Game Development

验证 Runtime 模块不依赖 Editor API：

```powershell
$buildArgs = @(
    '<ProjectName>'
    'Win64'
    'Development'
    '-Project=<Project>'
    '-NoHotReloadFromIDE'
)
```

### Game Shipping

验证 Shipping 宏、日志裁剪和测试代码边界：

```powershell
$buildArgs = @(
    '<ProjectName>'
    'Win64'
    'Shipping'
    '-Project=<Project>'
    '-NoHotReloadFromIDE'
)
```

## 4. 强制 UHT

反射声明、`UCLASS`、`USTRUCT`、`UFUNCTION` 或生成头发生变化时，可增加：

```text
-ForceHeaderGeneration
-WarningsAsErrors
```

UHT 通过仍不代表运行时或 Blueprint 行为正确；之后运行对应自动化测试。

## 5. 插件打包

单版本打包可直接使用 RunUAT：

```powershell
$uatExe = '<EngineRoot>\Engine\Build\BatchFiles\RunUAT.bat'
$uatArgs = @(
    'BuildPlugin'
    '-Plugin=<Plugin>\XTools.uplugin'
    '-Package=<Output>\XTools-Package'
    '-TargetPlatforms=Win64'
)

& $uatExe @uatArgs
if ($LASTEXITCODE -ne 0) {
    throw 'BuildPlugin failed'
}
```

本仓库多版本打包优先使用：

```powershell
.\Scripts\BuildPlugin-MultiUE.ps1 -Follow
```

## 6. 常见失败

- DLL 被 Editor 或 Live Coding 锁定：正常关闭 Editor 后重试。
- UHT 找不到类型：检查生成头位置、模块依赖和反射宏。
- Game Target 找到 Editor 头：拆分 Runtime/Editor 模块或修正 `WITH_EDITOR` 边界。
- UE 5.4+ 缺类型：按 IWYU 显式包含拥有该符号的头文件。
- 链接缺符号：根据导出符号所属模块修正 `.Build.cs`，不要凭模块名猜测。
- 增量构建状态异常：先确认目标和路径，再使用项目清理脚本；不要直接删除未知目录。

## 7. 验证顺序

1. `git diff --check`；
2. 受影响的 Editor/Game Target；
3. 对应自动化测试；
4. 发布前运行完整多版本 BuildPlugin 矩阵。
