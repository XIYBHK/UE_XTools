## 维护规则

1. 当前代码和配置是事实来源；文档与代码冲突时先核验代码，再修正文档。
2. 完成态计划、接手记录、审查流水和一次性构建统计不长期保留。
3. 通用经验应提炼为规则或指南，不保留工单编号和提交考古叙事。
4. 用户可见变更写入 `UNRELEASED.md`，发布后归档到 `CHANGELOG.md`。
5. 文档不写个人机器绝对路径、未经测量的性能数字或“最近/当前提交”等易腐烂表述。
6. 新增文档前先检查是否能合并到现有主题；删除文档时同步修复所有相对链接。
